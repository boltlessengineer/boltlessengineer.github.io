DB query on user request

imagine edit comment UI where pressing "edit" button changes comment element to editable textarea.

If this is implemented with HTMX hx-get="/comment/123/edit", the backend will run DB query just to render latest comment content.

This kind of "small DB query on small user interaction" happens everywhere.

UI interaction requires network request

e.g. when cancel the form

going back to previous UI state should be able to done locally, but with HTMX, it is usually handled through network

Solution - don't override the target on "edit" view?

only hide it and restore back on user cancel.

might be a good HTMX plugin idea
